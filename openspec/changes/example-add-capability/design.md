# Design: Add an Example Capability

## Backend Impact Assessment

| 维度 | 结论 | 事实依据 / 边界 |
|---|---|---|
| API / events | 涉及 | 新增一个受认证保护的同步读取接口；不发布事件。 |
| Data / storage | N/A | 结果由请求确定性计算，不保存用户状态或业务记录。 |
| Lifecycle / async | N/A | 单次同步请求，无队列、重试、删除或补偿。 |
| Identity / authorization | 涉及 | 仅已认证调用者可访问；不引入新角色或跨租户共享。 |
| Deployment / operations | N/A | 不新增进程、端口、环境变量或外部依赖。 |

档位：**B1**。若实现需要保存状态、调用外部服务或改变授权模型，必须升级为 B2/B3 并更新本设计。

## Context and Decision

现状没有受支持的能力入口。采用项目在已有服务中注册一个窄路由，复用既有认证中间件，并由纯函数完成输入校验与结果生成。

选择同步、无状态设计的原因：当前需求只需要立即返回确定性结果；加入数据库、任务队列或外部调用会扩大数据、生命周期和运维风险，而没有明确收益。

## API Contract

| 属性 | 约定 |
|---|---|
| Audience | 已认证的产品调用者 |
| Method / path | `<method> <path>`（采用项目替换） |
| Input | 已验证的最小请求字段 |
| Success | `200` 与确定性结果 |
| Primary errors | `401` 未认证；`400` 输入无效；`403` 无权限（若项目适用） |
| Idempotency / concurrency | 只读且无副作用；重复请求结果一致 |
| Async behavior | 无 |

## Security and Data Boundary

- 认证在路由处理前完成；
- 不记录口令、令牌、原始机密或不必要的个人数据；
- 日志只记录脱敏的错误分类和可关联的请求标识；
- 若能力需要租户或资源范围，必须从可信身份上下文获取，不能信任客户端传入的归属字段。

## Test Strategy

| 断言 | 层 | 理由 |
|---|---|---|
| 输入校验和确定性结果 | V1 | 无框架或网络依赖，最快且最稳定。 |
| 认证拒绝和路由契约 | V2 | 需要真实应用装配，但外部依赖可替身。 |
| 构建产物中路由可达 | V3（按项目适用） | 防止配置或打包导致的静默缺失。 |
| 真实页面/客户端入口 | V4（按项目适用） | 仅当用户路径、浏览器或外部边界本身是被测目标。 |

## Risks and Trade-offs

- 复用现有认证机制意味着该机制的可用性影响本能力；通过 V2 装配测试和 V3 冒烟覆盖。
- 将来若结果需要状态、审计或异步处理，必须升级档位并补充数据模型、生命周期、迁移、回滚和运行设计。

## Documentation Synchronization

实施时按实际改动更新：接口清单、认证/权限说明、部署配置说明、运行手册和能力主规格。没有变化的文档也应在 tasks 中注明复核结论。
