# 分层测试金字塔设计模板

本模板把“多写测试”转换为可执行的分层决策：每条断言应落在**能证明它的最低成本层**。层级不是按目录、语言或测试框架命名，而是按依赖边界和可观察事实命名。

## 1. 总体模型

```text
                    V4 端到端验收
              V3 构建产物与运行冒烟
         V2 集成、装配、接口与契约验证
             V1 单元、组件与领域行为
              V0 静态、类型与规则检查
```

自下而上，执行成本、环境不确定性和定位难度递增；测试数量应递减。V4 不是“更高级的单测”，它只验证浏览器、真实入口、部署形态或外部边界不可替代的事实。

## 2. 各层设计合同

| 层 | 被测事实 | 允许的依赖 | 必须具备 | 不应放入 |
|---|---|---|---|---|
| V0 静态 | 类型、格式、依赖图、配置形状、机密规则 | 编译器、静态工具 | 快速、确定、无网络 | 业务分支、真实服务行为 |
| V1 单元 | 领域规则、转换、边界、失败分类 | 进程内替身 | 输入到输出可读、毫秒级定位 | 容器、数据库、浏览器、框架装配 |
| V2 集成 | 模块装配、路由、序列化、契约、跨组件协作 | 进程内真实组件与替身外部依赖 | 自给自足；不读真实凭据；不需容器 | 云资源、共享环境、真实支付/身份/模型调用 |
| V3 冒烟 | 构建产物、运行配置、进程间连接、关键路径注册 | 受控本地或测试栈 | 可观察正向证据；明确启用项 | 组合爆炸的业务分支 |
| V4 e2e | 用户旅程、浏览器、真实入口、外部边界 | 真实部署形态与受控账号 | 资源隔离、清理、无重试掩盖 | 可由 V0–V3 覆盖的逻辑或路由细节 |

### 每层的完成判据

- **V0**：工具退出成功，规则覆盖新文件类型，未以全局忽略绕开新问题。
- **V1**：关键输入、边界、错误和不变量被断言；测试不依赖执行顺序。
- **V2**：真实组装下的端点、消费者或组件可达；外部调用被显式替身化；至少一个依赖缺失或拒绝场景被验证。
- **V3**：实际产物启动后，目标能力有正向证据，例如目标路由的预期响应、注册日志、可查询状态或关键事件；`health` 单独为绿不足以证明能力装配。
- **V4**：真实入口完成用户操作并出现用户可感知结果；请求未被开发代理、mock 或注入令牌旁路替代。

## 3. 断言放置决策树

```text
要验证的事实
  ├─ 仅依赖纯逻辑或单一组件？ → V1
  ├─ 需要框架组装、路由、序列化或模块协作？ → V2
  ├─ 需要证明构建产物、配置、进程或关键依赖已生效？ → V3
  ├─ 需要浏览器、真实登录、真实部署入口或外部系统交互？ → V4
  └─ 仍不确定？
       ├─ 先写 V2，列出缺失的不可替代事实
       └─ 只有这些事实无法由 V2/V3 获得时才新增 V4
```

新增 V4 用例必须写出：**为什么 V2 或 V3 无法覆盖该断言、创建什么资源、如何命名、如何清理、失败时谁负责排障**。

## 4. B0–B3 与最低验证组合

B 档位是风险分级，不是工作量估算；一个变更按最高涉及档位处理。

| 档位 | 定义 | 最低验证 | 常见增加项 |
|---|---|---|---|
| B0 | 无后端影响，例如纯文档或非行为性样式 | V0；按前端风险补 V1 | 可访问性或视觉回归 |
| B1 | 同步适配，无持久化、无跨服务副作用 | V0 + V1 + V2 | V3 验证运行时注册或配置生效 |
| B2 | 新增/修改持久化状态或用户可见状态 | V0 + V1 + V2 + V3 | 迁移前后、并发、幂等、权限、保留和回滚；必要时 V4 |
| B3 | 跨服务、外部资源、异步删除/过期、高权限或不可逆风险 | V0 + V1 + V2 + V3 + 有针对性的 V4 | 故障注入、重试/补偿、权限拒绝、可观测性、演练和人工复核 |

B2/B3 不能只依赖 V4：真实环境失败的诊断成本最高，契约、数据约束和生命周期错误应先在 V1/V2/V3 截获。

## 5. V2：集成层的关键模式

### 装配契约

每个能独立注册路由、消费者、任务处理器或插件的单元，至少验证：

1. 正确配置下目标能力已注册或可达；
2. 不存在的相邻路径/未知事件不被误匹配；
3. 关键依赖缺失时是明确拒绝、受控降级还是启动失败；
4. 对外契约可被导出或集中校验，避免前后端路径靠人工同步。

### 外部依赖替身

V2 可以使用 HTTP stub、内存队列、fake clock、临时目录或内存数据库，但必须保留真实调用协议和错误形状。禁止把业务调用点整体 mock 掉后再宣称验证了集成。

### 前端集成

页面测试经真实 API client 发请求，由网络层替身返回契约化响应。这样能验证路径、请求体、认证头、错误映射和状态更新，而不是只验证组件 props。

## 6. V3：冒烟的最小闭环

V3 只覆盖“低层无法证明的装配事实”。每个检查应包含：前置、动作、预期正向证据、失败信息和清理。

| 检查目标 | 合格证据 | 不合格证据 |
|---|---|---|
| 扩展/插件已加载 | 专属 health contributor、注册表项、目标日志或真实端点 | 进程存活、通用 health 为 UP |
| 配置已绑定 | 受控请求体现配置行为或暴露受限诊断 | 环境变量存在 |
| 鉴权链生效 | 合法/非法身份获得不同预期结果 | 只有匿名请求被拒绝 |
| 发布物正确 | 运行的是构建产物且关键资源可读 | 源码开发服务器可访问 |

条件化启用的检查必须输出执行数和跳过原因；断言数减少应视为潜在静默跳过，而不是自动通过。

## 7. V4：真实链路纪律

### 资源隔离

共享环境中，每个资源名使用：`<run-prefix>-<kind>-<worker>-<sequence>`。前缀由运行器注入，不能只依赖当前时间。测试结束按唯一 ID 清理，失败时输出可定位的残留资源列表。

### 认证与状态

真实登录、换票、重定向或浏览器存储是被测行为时，必须走真实流程。可复用登录态时，先单独验证它仍有效；业务用例不得偷偷自动重登以掩盖登录态寿命问题。

### 外部依赖

外部限流、配额或故障应以明确分类失败呈现；不要加 retry、扩大 timeout 或把错误转成 skip。若外部依赖不属于本变更验收范围，将断言下移到 V2 的协议替身测试。

## 8. 时间预算与不稳定性

每层应记录：执行时长、断言/用例数量、运行时刻和提交标识。设定本机 `warn` 与 CI `enforce` 两种模式：本机超限仍需调查，CI 超限应阻止发布。

处置顺序：下移断言 → 消除重复准备 → 修复资源争用/串行瓶颈 → 说明理由后调整预算。明显变快也要调查，常见原因是测试被删除、过滤或跳过。

“原样重跑转绿”必须登记：层级、用例、外部依赖、症状、次数、首次/最近时间、临时处置、负责人和截止点。达到团队阈值后，必须修复、隔离依赖或下移断言。

## 9. 采用检查表

- [ ] 每个层都有唯一命令入口和明确前置。
- [ ] V2 不读取真实凭据、不依赖容器或外部服务。
- [ ] V3 对每个启用能力有正向装配证据。
- [ ] V4 有资源命名、清理、真实入口与失败分类规则。
- [ ] B0–B3 已映射到最低验证组合。
- [ ] 时间预算、断言数和不稳定性登记有唯一事实来源。
